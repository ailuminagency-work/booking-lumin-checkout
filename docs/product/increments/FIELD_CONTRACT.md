This increment adds a 19-kind capability registry and a separate schemaVersion 1 text definition/answer contract. Only text has contract support; renderer, persistence and publication capabilities remain disabled. Existing V1/V2 publication and price-bearing Selection are unchanged.

parseTextFieldDocument validates at most 64 uniquely keyed text definitions. parseTextAnswers accepts at most 64 keyed answers, rejects unknown/duplicate keys and missing required values, and returns copied frozen data. Keys are bounded ASCII identifiers. Length is measured in Unicode code points, capped at 4096; malformed surrogate sequences and line separators are rejected. Exact strings are preserved without normalization. Whitespace-only required answers fail; optional empty/whitespace answers bypass minimum length but must satisfy maximum length. Raw request-byte limits remain the responsibility of future HTTP integration. Reflection may invoke proxy traps; exceptions fail closed, and accessor values are not read.
