The embed specification requires dropdowns with stable choice IDs. Existing strict V2 documents and migration0034 support text/textarea only, so this increment adds an explicitly versioned pure V3 contract instead of widening accepted readers or storage. It grants no authorization and activates no runtime, renderer, editor, publication, persistence or pricing behavior.

V3 mixes existing text/textarea semantics with dropdowns. Fields are bounded to64; each dropdown has1–32 choices and the document has at most256 choices. Each choice has a stable key-shaped ID and an exact bounded plain-text label. IDs are unique within each dropdown; duplicate display labels are permitted because identity comes from IDs. Text metadata and answers retain existing V2 Unicode/length rules. Dropdown answers contain one declared ID; unanswered optional fields are omitted, empty or unknown selections reject, and required answers must be present. The aggregate answer limit remains65536 UTF-16 units. No defaults, price/effects, arbitrary expressions or Selection conversion are supported.

Parsers must reject unsupported versions, unknown keys, malformed Unicode, duplicate fields/answers/IDs, prototype and descriptor attacks, sparse arrays and unbounded input. Returned data is detached and deeply frozen. Callers remain responsible for raw request-byte limits before JSON decoding; reflective Proxy traps cannot be prevented, but failures reject. No accepted V1/V2 source or SQL changes.
