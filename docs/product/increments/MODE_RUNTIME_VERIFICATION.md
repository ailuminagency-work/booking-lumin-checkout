## Decisions needed in the implementation freeze

These are finite expected-outcome choices, not permission to let tests choose production behavior. Root/contract author must resolve them before implementing assertions:

1. Exact classic IIFE entry/discovery rules for the unchanged deferred composeInstall snippet, duplicate scripts, containers inserted later, removal/reinsertion and explicit disposal. Capture currentScript synchronously. Trusted compiled R/manifest authority cannot come from merchant attributes. No own-final-hash embedded inside its own hashed bytes.
2. Child asset path/MIME/integrity/crossorigin and success CSP strategy, exact permitted A connection, cache/HEAD/error/redirect rules. Existing error CSP remains all-none. Bind actual emitted-byte digests to a newly created synthetic profile through accepted fixture operations, never alter immutable installation identity.
3. Hosted readiness meaning with no parent handshake; iframe state after an enabled policy/target revision change; removed-parent/failed-refresh terminal behavior. Specify whether only explicit remount recovers. The current protocol has no parent revocation message: test child unavailability separately from parent knowledge.
4. Parent admission versus retained cleanup accounting, unresolved-operation caps, timeout/removal behavior, bfcache/reload generations, entropy failure and clock failure. Eight visible frames cannot conceal unlimited abandoned work. Do not assume the portable reader's cap applies to a separately implemented child reader.
5. Resize measurement source, initial measurement, fixed versus rolling four-per-second definition, trailing coalescing and timer ownership. Define the precise retry time origin, policy refresh no-overlap rule and hidden-to-visible behavior.

## Finite controlled/adversarial complement

Separate fixed groups U01-U08 with explicit positive/negative neighbors. These use trusted clock/entropy/network seams and native messages/streams where applicable; label them controlled, not real elapsed-time browser proof.

- U01 constructor/profile/manifest/attribute parsing: own-data descriptors, unknown keys, accessors/prototypes, mutable caller objects, canonical UUID/height, no data-api authority, registration mismatch and exact accepted message parser/1024 UTF8 limits. V1 astral data must not be narrowed by V2 validators.
- U02 handshake clock: sends at 0/500/.../4500 only; no send at 5000; pre/post boundary ready and policy settlements; listener registered before policy work; one pending init, repeat coalescing/conflicting-instance denial; init cap 10 per 5 seconds with the frozen window rule.
- U03 policy reader: 1999/2000 deadline neighbors including after cleanup/final settlement, malformed/disabled/profile-mismatched DTO precedence, nonfinite/backward/throwing clocks, clearTimer/setTimer failures, caller abort and bounded close. Never release unresolved work on outward timeout alone.
- U04 rate/resize: exact four-per-second window boundaries, no double trailing send/application, latest coalescing, integer bounds and teardown invalidating delayed callbacks.
- U05 admission/lifecycle: eight/ninth, entropy throw/reentrancy/reservation, duplicate execution, removal/reinsertion, pagehide/bfcache generation and failed mount accounting. Late old callbacks cannot release/reuse a new owner's slot.
- U06 refresh: 30-second boundary, hidden suspension, visibility/background coalescing, no overlap, rejected/late read and committed revision transition behavior. Final state must be determined after the final clock/abort sample.
- U07 retained cleanup: truly hung fetch/read/cancel/observer cleanup at exact configured cap; reject new work without growth; eventual late settlement releases only its owner. Close stays within its independently bounded contract even if cleanup never settles.
- U08 output/authority: exact executable HTML escaping/template roundtrip, child asset CSP/SRI and response errors/HEAD; no dynamic import/session-client dependency or arbitrary action callback. Verify actual built graph, not only source grep.

Root should reserve these tests separately from product authors where possible. Author tests plus independent review remain useful, but author tests alone do not satisfy the independent adversarial gate. The verifier does not self-approve its own test source.
