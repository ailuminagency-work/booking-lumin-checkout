## 7. Wire outcomes and HTTP status

Preserve typed repository outcomes exactly inside the versioned envelope; never use SELECT receipt as success. Committed receipt and completed data200. Committed/completed withheld or unknown_commit/completion_uncertain202, still no missing receipt fabricated. A browser receiving a complete authenticated fixed pre-dispatch error may report rejection; any ambiguous fetch/parse/overflow/disconnect outcome AFTER dispatch remains delivery-uncertain locally. Never invent a repository rollback classification from HTTP status alone. Safe UI messages map enums, not SQL/driver text.

An irreversible per-request dispatchStarted latch begins false and is set immediately after the final admission/authority/body checks, directly BEFORE invoking the selected repository method. The method invocation itself counts as dispatch even if it throws synchronously. There is no await between final checks and latching/invocation. Profile GET and rejected preflight never dispatch a repository. Once latched, every handler/catch/deadline/serialization/overflow/shutdown branch is forbidden to emit phase:not_dispatched. This is true for reads as well as mutations. A valid fully checked typed repository outcome may still communicate its own known transaction/read state; the wrapper does not reinterpret it.

Before writing headers, validate and serialize the entire repository_result envelope to a bounded byte buffer. Any unexpected code, invalid result, thrown serializer, wrapper overflow, deadline or transport error after dispatch without a safely deliverable typed outcome uses exact {schemaVersion:1,phase:'delivery_uncertain',operationKind:'mutation'|'read',code:'OUTCOME_UNAVAILABLE'} with HTTP202, no receipt/data/transaction label. Use one of two prebuilt constant byte buffers for this fallback so a failed general serializer is not called again. If headers/body have already begun or the socket cannot send safely, destroy the owned response socket instead; never append a second JSON envelope or a pre-dispatch rejection. Consume the repository's eventual settlement without delivering a late second response.

Client requires an exact recognized phase and complete bounded body. Completed operation-recovery receipt has the same historical meaning; it must never overwrite current version/policy with old receipt values. Current controls use only fresh owner list/current flow pointer after recovery. A refresh failure keeps mutations locked and says Recorded; current settings unavailable.

Typed known not_started, rolled_back or no_commit_submitted failure can clear that CURRENT mutation if there was no earlier delivery uncertainty for the key.
