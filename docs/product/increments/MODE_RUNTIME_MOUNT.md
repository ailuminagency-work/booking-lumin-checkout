## 1. Exact compatibility and scope

Keep composeInstall unchanged. Its iframe output is one div with `data-booking-lumin-installation="<canonical UUID>"` and `data-booking-lumin-height="640"`, followed by a newline and `<script src="<canonical R loader URL>" defer></script>`. It has no module type, mount invocation, profile attribute or API attribute. Hosted output remains an R URL and does not load a merchant controller.

Deliver a self-contained classic IIFE with synchronous entry, not a module-only export. The IIFE captures `document.currentScript` before any promise, timer or event callback. It registers and immediately attempts its own preceding container. Root owns emitted asset registration and the rest of the child/document contract. This proposal specifies parent mount ownership only; the child still independently enforces fresh policy, direct-parent origin and message validation. Ready means a channel initialized, never that booking is operational. No session/request/payment call, form activation or token is introduced.

## 2. Script identity without self-hash embedding

Capture the current script element, its raw src attribute and its previousElementSibling synchronously. Require a native HTMLScriptElement belonging to this document, connected in the light DOM, with no module type (absent or empty type for this supported output). Require an absolute raw src exactly equal to canonical configured R plus `/assets/booking-lumin-loader.` plus 64 lowercase hexadecimal characters plus `.js`, with no query, fragment, credentials or normalization alias. Do not accept a relative raw attribute merely because the DOM src property resolves it. The merchant page must be a canonical supported HTTPS origin M distinct from compiled R/A/P. These are supported-topology checks, not merchant authentication.

The loader bytes may embed the supported runtime ABI and trusted R/A/P/profile registration needed by the root contract, but MUST NOT embed their own final loader digest or full final hashed loader URL. Root emits the bytes, computes their digest, and then creates the trusted server manifest/profile/install fixture. The R asset server serves only that exact registered path and exact bytes; independent build/browser tests prove this binding. The parent can check the observed src grammar/R, but cannot prove from currentScript alone that no redirect occurred or that its bytes match that path. No stronger runtime proof is claimed. Parent SRI would require a separate deliberate composeInstall contract change and is not smuggled into this unchanged-snippet leaf. Child asset integrity remains root's separate decision.

Merchant attributes never select A, P, profile registration, executable child URL, arbitrary iframe URL or callbacks. A same-origin merchant script can mutate its own realm and this cooperative registry; none of its globals confer private API authority.

## 3. Discovery and registration

Discovery is exclusively `capturedScript.previousElementSibling`, never document.querySelectorAll, nearest ancestor search, ID-based lookup or a whole-document scan. Whitespace/comments between the two elements are harmless. The candidate must be a connected native HTMLDivElement whose ownerDocument is this document, outside shadow DOM, with exactly the two supported data attributes relevant to this runtime. Other ordinary merchant attributes such as class, id and aria labels do not grant authority. Installation ID uses the accepted canonical UUID parser. Height is a canonical decimal integer in 320..1600; absent height defaults to 640. Reject padded/sign/exponent/fraction/whitespace forms. The real generated height640 is an explicit positive control.

Require no child elements and no non-whitespace text on first registration. Do not erase merchant content. Append only one owned iframe; do not rewrite container.innerHTML or set style text from input. The iframe has fixed title `Booking form`, width100%, the selected numeric height, sandbox exactly `allow-scripts allow-forms allow-same-origin`, and canonical R `/embed/flow/<installationId>` src. No token, parent-origin query, profile query or arbitrary URL is added. The parent must be top-level (`window.parent === window`); nested merchant mounts fail before iframe creation. Actual CSP tests still separately prove all-ancestor enforcement.

A successful registration stores an immutable binding in a WeakMap keyed by the container: installation ID, observed canonical loader URL, selected height and runtime identity. No selector or DOM-node list is retained. Registration itself starts no network work. Each script attempts only that one candidate, so N pasted snippets produce N bounded individual attempts, without an O(N squared) page scan. A malformed candidate does not become a reusable registration. Script insertion via innerHTML does not execute a classic script and is not advertised as supported automatic discovery; dynamically appending a real script immediately after its container does execute the same entry path.

## 4. One document owner and bounded public surface

Proposed public name: `window.BookingLumin`. Define it once as a frozen, non-writable, non-configurable value with exactly `protocolVersion: 1`, `mount(container)` and `unmount(container)`. No registry, instance ID, frame/window reference, policy, raw result or mutable collection is returned. Functions do not accept options, URLs, installation IDs, callbacks or action names.

`mount(container): "mounted" | "already_mounted" | "unregistered" | "invalid_container" | "capacity" | "suspended" | "unavailable"` is synchronous. It only remounts a container previously registered by an actual supported script entry. It rechecks connectivity, empty/owned DOM state and unchanged binding attributes; changing installation or height requires a new container and its paired script. `mounted` means an iframe was admitted, not ready or operational. `unmount(container): boolean` synchronously disposes an active owned mount, returning true only when it disposed one. It retains only the weak registration, permitting a later explicit mount. Arbitrary merchant divs cannot be registered by calling this API.

Duplicate IIFEs obtain the existing singleton through one fixed non-enumerated coordination property, proposed `Symbol.for("booking-lumin.mount-owner.v1")`. The coordination record is frozen and exposes only an ABI/runtime compatibility check and a register-and-attempt operation to subsequent copies. It is not a security secret. Compare compiled ABI version plus exact R/A/P/profile identity; a different incompatible build/profile must fail closed without replacing or closing the first owner. Repeated copies of the compatible runtime, including independently emitted same-ABI assets accepted by the root manifest, share the original owner. A preexisting public-name/coordinator collision or incomplete/inconsistent pair returns without mounting, replacing globals or polling for recovery. Constructor validation occurs before either property is installed; guard partial installation failure as terminal entry failure. Root should adopt these literal names or explicitly substitute them before freeze.

Strong registry capacity is exactly eight admitted mounts per document, shared across all compatible script executions, installations and loader tags. Pending load, pending ready and ready mounts all consume a slot. Reserve the slot before entropy, iframe creation or observer/listener installation. Use 16 cryptographically random bytes and the accepted32-lowercase-hex instanceId. Entropy throw/failure releases the reservation and creates no frame. The ninth attempt returns capacity and creates no iframe or queued retry. Removing another mount does not automatically start a previously denied one: the merchant can explicitly call mount on its weakly registered container. Duplicate entry on an active container returns already_mounted without another ID, iframe or timer. Duplicate entry after failure/disposal does not silently retry; only the explicit mount API starts a new generation.

## 5. Lifecycle and ownership

Per active slot retain only one container, owned iframe/window reference, immutable binding, random instanceId, monotonically increasing local generation, finite state and the root-frozen bounded protocol timers. Reuse accepted message parser and source/origin/installation/instance checks. Every callback additionally verifies slot identity, generation, active state and current container/frame connectivity. Never accept a frame moved out of its owned container or a detached container merely because its contentWindow still matches.

Before each mount attempt, message, load callback and scheduled scan, sweep at most eight active slots for disconnected containers, wrong ownerDocument, moved/replaced owned iframe, changed binding attributes or unexpected added child content. Dispose invalid ownership before performing protocol work. Do not remove the merchant's replacement content. To catch removal even without subsequent events, keep one shared250ms connectivity timer only while at least one slot exists. Each tick visits at most eight slots; no whole-document MutationObserver with an unbounded mutation-record backlog, per-container observer or DOM scan is required. This makes removal cleanup bounded by the next runnable timer (background suspension can delay browser timers); event-path checks deny stale messages immediately. Do not promise wall-clock execution while the browser is suspended.

First iframe load begins the existing5s handshake and500ms retries, maximum10 sends. A second load on the same generation is terminal, even after ready: dispose the channel/frame and require explicit remount. Root's controller contract defines precise clock sampling and resize rules; mount ownership must not reset those budgets. Late ready/resize/load/timer callbacks from a failed or disposed generation do nothing. A successful ready must not allocate a second slot or new generation.

Disposal marks state terminal and invalidates generation first, then removes owned listeners/timers and the owned frame if still present; it never clears unrelated merchant nodes. Release the strong slot exactly once. Remove the shared message listener and connectivity timer when no active slot remains. Maintain only a fixed pair of page lifecycle listeners with the document singleton; repeated scripts do not add these listeners. Expected frame removal does not add a new slot. A terminal scheduler/clock failure closes this document owner to further admission, disposes every mount and never establishes a new baseline.

On pagehide, synchronously suspend admission and dispose all eight or fewer mounts. Retain only weak registrations and fixed lifecycle listeners. On pageshow with persisted=true, clear suspension only if the owner has not suffered a terminal fault, but do not automatically remount. Merchant code may explicitly call mount, obtaining new entropy/generation and a fresh child document/policy. On an ordinary new navigation a new document obtains its own owner. A failed handshake, removed frame or revoked child remains failed until explicit remount; no automatic reload/retry loops.

The parent itself performs no fetch, response stream or cancellation work. Therefore freeing its DOM slot does not claim a promise in the child has settled. Child unresolved-reader admission and teardown accounting must be bounded by the separate child contract; a parent cannot count or attest another destroyed realm's network cleanup. Actual verifier tests must distinguish document/frame slot reclamation from child unresolved work and bound repeated remount behavior at the A/server boundary. Eight parent slots alone are not evidence that total system work is bounded.

## 7. Decisions root must integrate before freeze

This proposal chooses previous-element discovery, a fixed small public API, shared compatible-runtime singleton, explicit retries/remounts, eight strong slots, weak registration and bounded scanning. Root must reconcile the exact public/coordinator names, compatibility identity and build-injected registration with its asset contract; define the child's unresolved-fetch cap and remount/server rate proof; and freeze exact child ready/refresh/resize semantics. Parent cannot solve those by inventing a session bridge or asserting cryptographic authenticity of its own currentScript.

No implementation authorization follows from this handoff. The visible customer document remains unavailable until later runtime/session gates. Real authentication, production token/restart semantics, registry/provider activation, hosted ingress/Netlify precedence and complete W3 customer workflow remain explicit downstream work.
