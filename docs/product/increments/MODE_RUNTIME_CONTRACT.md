## Asset graph and trusted authority

Use two self-contained classic IIFE bundles without eval, dynamic imports or inline execution. Build parent loader FIRST with compiled canonical R only and fixed protocol constants. It captures document.currentScript synchronously, checks its absolute canonical src is at compiled R and the accepted loader pathname grammar, and never embeds its own final digest. Compute SHA256 of emitted loader bytes; then build child controller with the trusted full installation profile whose loaderUrl uses that digest. Compute child digest last. Manifest binds profile, both exact emitted byte hashes, MIME and names. This directed build graph has no self-hash cycle. P in the compiled platform profile is routing metadata, not a customer field or credential; public-policy DTO stays unchanged.

Names: existing /assets/booking-lumin-loader.<64lowerhex>.js and new /assets/booking-lumin-controller.<64lowerhex>.js. No extra bundles/source maps at the public asset boundary. Server registration validates exact manifest keys, canonical profile, both bytes/digests and a 262144-byte per-bundle cap before starting; no request/header/attribute supplies registry or asset authority. A fresh local synthetic profile uses the actual loader hash; accepted SQL/migrations remain unchanged. Registration failure is startup failure, never an inert fallback reported as successful runtime.

Dedicated asset GET/HEAD serves only the two registered exact raw paths, exact R Host and accepted header constraints. Unknown files404; malformed aliases/query/fragment/raw escapes400; other methods405; never redirects/SPA/index fallback. application/javascript;charset=utf-8, nosniff, no-referrer; immutable hashed success caching allowed for code only. All asset errors use fixed minimized bodies and all three no-store headers. Static anonymous CORS '*' may be emitted without credentials; assets contain no customer/secret data. Root freeze will specify exact cache strings before implementation.

## Child state and freshness

States STARTING_POLICY, AWAITING_INIT, READY, TERMINAL. Hosted mode validates fresh policy and never waits for init, emits ready/resize or creates a parent channel. Iframe mode accepts only a direct parent (parent!=window and parent==top), exact current allowed M, source identity, canonical installation/instance and T1 protocol. Keep at most one pending valid init; repeats coalesce; conflict never replaces it. No ready until fresh policy success and valid init. Emit ready at most once for this generation. Remain visibly unavailable for booking even when the distribution channel is READY.

Parent's5s handshake begins at its first owned iframe load; sends at0,500,...4500ms only. No send or acceptance at/after5000ms. Capture trusted monotonic clock methods and cryptographic16-byte entropy once. Source/origin/instance matches required on every ready/resize. Any later frame load ends the channel instead of silently rebinding. No wildcard postMessage.

Refresh while active every30s, anchored to previous read start, plus a visibility-to-visible trigger. At most one read runs; triggers coalesce to at most one pending refresh. Every read has one2s total budget covering delivery and cleanup. A read failure/timeout, invalid/disabled policy, target/policy revision change or parent removal closes the child terminally. No repeated ready, automatic reload or recovery. Explicit external remount creates a new generation. Unchanged successful policy preserves readiness. Parent has no authenticated revocation message in T1; never claim parent is notified when child becomes unavailable.

## Capacity, resize and teardown

Child owns at most one unresolved policy fetch per document. Timeout/abort does not free its retained cleanup accounting until actual settlement; timeout makes this document terminal so no further reads can accumulate. Terminal clock or cleanup failure permanently closes admission. Parent owns no policy fetch and does not retain child promises. It owns at most8 frame/channel records, listeners and timer handles; lifecycle/mount proposal will define exact shared registry and slot reuse.

Removing an iframe releases only its parent DOM/channel resources after their cleanup; it does not prove immediate server-query cancellation. Cross-origin parent cannot observe internal child transport settlement through the existing protocol. Server API's independent unresolved-backend/admission/rate limits remain necessary and tested. Do not claim a global browser/server cancellation bound from DOM removal. Stress removed/remounted frames against unresolved reads and assert both bounded parent ownership and actual API backend caps.

Resize measurement is ceil(max(documentElement.scrollHeight,body.scrollHeight)) clamped320..1600. Only READY iframe channels send; hosted never sends. Fixed monotonic1000ms windows permit4 sends and4 parent applications, with one trailing latest-value coalesced timer. Parent initialheight from accepted snippet/default640. No post-close timer/application; no arbitrary callback or customer-runtime action API. Actual DOM content/viewport changes in the fixture exercise measurement.

Pagehide terminates channels; persisted pageshow does not silently remount. Container removal disposes its frame/listeners/observers/timers and invalidates generation before late callbacks. Entropy failure is terminal mount failure. Explicit reinsert/new snippet execution may allocate a new generation according to the reviewed mount proposal. No state/token in localStorage, sessionStorage, cookies, URL, referrer or parent messages.
