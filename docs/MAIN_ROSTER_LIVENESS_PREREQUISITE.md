# Roster client liveness prerequisite

This isolated Wave 4 review branch addresses an inherited roster transport defect: invalidation previously waited for a pending fetch or body read to settle, and requests had no total deadline. The intended client behavior is prompt local settlement on invalidation and one 15-second total asynchronous deadline, even when an injected fetcher or stream ignores cancellation. The browser's abort request does not prove a server write stopped or rolled back. Timed-out mutations retain an unknown outcome; callers must refresh authoritative state before another change.

Base: `ab8942e9d7a7e53a7f000b4463475c052d962ba4` (`codex/main-owner-shift-client`). Scope is the roster transport, its source-adjacent tests, one existing Portal roster regression test updated for cancellation, and this evidence note. There is no Portal runtime call-site change, server, SQL, worker authorization, payment, provider, deployment or protected-main change. Existing server-side membership, CAS, booking and capacity authority remain necessary. The deadline is bounded by JavaScript event-loop scheduling, not a hard real-time guarantee.
